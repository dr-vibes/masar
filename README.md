# مسار — مساحة العمل الشخصية للوساطة العقارية (V2)

> **وثائق مرجعية ملزمة عند التطوير باستخدام AI:** ابدأ بـ [`PROJECT_CONTEXT_AR.md`](PROJECT_CONTEXT_AR.md) و[`AGENTS.md`](AGENTS.md) ثم [`CHANGELOG.md`](CHANGELOG.md). الخارطة المحدثة في [`docs/ROADMAP_AR.md`](docs/ROADMAP_AR.md)، ودليل تشغيل AWS في [`docs/AWS_RUNBOOK_AR.md`](docs/AWS_RUNBOOK_AR.md)، ونقطة الاستئناف في [`docs/HANDOFF_AR.md`](docs/HANDOFF_AR.md). **كل تغيير/أمر تشغيلي يُوثّق في سجل التغييرات فورًا.** الفحص المحلي `npm run docs:check`، وإعداد GitHub Actions الذي أُضيف للمصدر سيشغّل الاختبارات والبناء وفحص تحديث السجل عند دمج التغييرات بعد رفعه إلى المستودع.

نسخة مطوّرة من المشروع الأصلي لتناسب استخدام مستشار يعمل داخل مؤسسة وساطة عقارية، مع مسارين مرتبطين بعمله اليومي:

1. **التمويل العقاري:** استقبال العميل ← بيانات الدخل والالتزامات ← حساب تقديري لكل بنك وفق شروطه وشرائح تسعيره ← مقارنة ← اختيار بنك ← حفظ الملف ← استكمال المستندات ورفع الطلب ومتابعة النتيجة.
2. **إيجارات المشاريع:** إضافة المشروع ← إضافة الوحدة والمستأجر والعقد ← الاستحقاقات الشهرية ← تسجيل دفعات جزئية أو كاملة ← متابعة المتأخرات ← تقرير CSV.

> **تنبيه أساسي:** هذه النسخة تُخزن البيانات داخل `localStorage` على نفس الجهاز والمتصفح، دون حساب مستخدم أو قاعدة بيانات أو تشفير للبيانات المخزنة. هي نسخة تشغيل وتجربة **وليست جاهزة لبيانات العملاء الحقيقية أو النشر العام على Netlify**. لا تضع فيها بيانات شخصية أو بنكية حساسة حتى إضافة تسجيل دخول آمن، وقاعدة بيانات مع ضوابط وصول ونسخ احتياطي وخطة امتثال مناسبة.

## تشغيل المشروع

يتطلب Node.js حديثًا وnpm (استُخدم Node 24.22.3 بنجاح على خادم AWS أثناء البناء):

```bash
npm ci
npm run dev
```

افتح عنوان Vite المحلي الظاهر في الطرفية، ثم `/app` لعرض لوحة العمل. للإنتاج بعد تهيئة إجراءات الأمان:

```bash
npm run build
npm run preview
```

ملف `netlify.toml` يدعم Vite (`dist`) ومسارات React Router، لكن **نشر نسخة frontend لا ينشئ Backend ولا يحمي البيانات**.

## الصفحات

- `/app`: لوحة العمل ومؤشرات التحصيل والطلبات.
- `/app/calculator`: حاسبة الاستحقاق وحفظ أو تحديث ملفات العملاء.
- `/app/compare`: مقارنة العروض النظرية للبنوك.
- `/app/clients`: حالة طلب التمويل ومرجع البنك وتاريخ رفع الطلب وملاحظات المستشار ومواعيد المتابعة.
- `/app/rentals`: المشاريع والوحدات والعقود والتحصيل الشهري والمدفوعات الجزئية والمتأخرات.
- `/app/rates`: إعدادات كل بنك، شرائح التسعير، إعدادات المؤسسة، النسخ الاحتياطي والاستعادة.

## إعداد سياسة بنك

1. من «قواعد البنوك والإعدادات»، اختر البنك ثم حدِّد الحد الأدنى للدخل، القطاع المقبول، الحد الأقصى لمدة التمويل، الدفعة الأولى، وحد العمر عند انتهاء التمويل **إن كانت هذه الشروط معروفة ومؤكدة لديك**.
2. أدخل النسبة الافتراضية للحكومي/العسكري والخاص، واختر نموذج الحساب «رصيد متناقص» أو «هامش ثابت» بحسب السياسة الفعلية للبنك. كلا النموذجين في البرنامج **نماذج حسابية افتراضية** وليسا وصفًا رسميًا لمصرف بعينه.
3. يمكنك إدخال «شرائح» وفق القطاع (مدني/عسكري/خاص)، الدعم السكني، تحويل الراتب إلى البنك، حد الدخل الأدنى والأعلى، والنسبة الخاصة بالشريحة. تُجرَّب الشرائح **من الأعلى للأسفل** ويُطبّق أول تطابق؛ وإلا تُستخدم النسبة الأساسية للقطاع.
4. أدخل **مصدر السياسة وتاريخ تحديثها** عند التأكد من بيانات البنك. لا تعتبر القيم المرفقة بالبرنامج نسباً مصرفية صحيحة؛ إنها أمثلة تجريبية من المشروع الأصلي.
5. عند إدخال حالة العميل، يعيد النظام حساب أهلية كل بنك والمدة والقسط ومبلغ التمويل وفق إعداداته. عند اختياره وحفظ الملف، يُحفظ **ملف الحساب والجهة المختارة** محليًا، ثم يمكن متابعة طلبه من صفحة العملاء.

### حدود الحسابات

- افتراضات الاستقطاع العامة وحد دخل 15,000 واحتساب البطاقات والتقاعد قابلة للمراجعة، وليست محرك أهلية معتمدًا من مؤسسة مالية أو جهة تنظيمية.
- المعدل المدخل هو معدل حسابي اسمي وليس **معدل النسبة السنوي الفعلي (APR)**؛ الرسوم والتأمين والتكاليف الإضافية وغيرها غير ممثلة.
- نموذج «التمويل المرن» يزيد مبلغ القسط العقاري بعد انتهاء القرض الشخصي عندما يتيحه إعداد البنك، لكنه لا يتعامل مع جميع صيغ إعادة الجدولة أو الحالات الفعلية.
- مقارنة «أعلى مبلغ» ليست توصية نهائية، ولا تمثّل موافقة أو إمكانية رفع طلب تلقائيًا؛ رفع الطلب يتم لدى البنك خارج التطبيق، وداخل مسار يُسجَّل تقدمه فقط.
- الأدلة المستندية الفعلية أو ملفات الهوية وكشوف الحساب **غير مُرفقة في هذه النسخة** لتجنب تخزين بيانات حساسة في المتصفح.

## تحصيل الإيجارات

- اعمل على شهر واحد في كل مرة في شاشة التحصيل؛ يمكن الرجوع إلى شهر قديم لتسجيل دفعة مستحقة له.
- لا تُحسب قيمة إيجار مجزأة على أيام؛ أي شهر يقع داخل فترة العقد يحتسب فيه إيجار كامل.
- يوم الاستحقاق 31 في شهر أقصر يتحول تلقائيًا إلى آخر يوم من ذلك الشهر.
- المدفوعات تُسجّل مبلغها وتاريخها وطريقة الاستلام ومرجعها، وتؤدي إلى تحديث المتبقي.
- تُعرض متأخرات جميع الأشهر السابقة حتى الشهر الحالي، ويتم منع تسجيل مبلغ أكبر من المستحق للوحدة والشهر المختارين.
- تقارير CSV للمتابعة وليست إيصالات دفع رسمية أو فواتير ضريبية، ولا يوجد ربط بمنصة «إيجار» أو البنوك أو أنظمة الرسائل.

## الحفظ والنسخ الاحتياطي

استخدم «إعدادات ← النسخ الاحتياطي» لتنزيل ملف JSON واستعادته. ملف النسخة الاحتياطية **غير مشفّر** ويحتوي على بيانات العمل؛ يجب حفظه بأمان. الاستعادة تستبدل جميع سجلات النسخة الحالية. حذف بيانات الموقع أو استخدام متصفح آخر قد يُفقد البيانات. نظام النسخ الاحتياطي اليدوي **ليس بديلاً** عن قاعدة بيانات مؤمّنة.

## خارطة الطريق للمرحلة الثانية

1. **الأمان أولًا:** تسجيل دخول، قاعدة بيانات محمية (مثل Supabase/PostgreSQL)، صلاحيات على مستوى المستخدم، إدارة الأسرار والنسخ الاحتياطي، وسياسة للبيانات والاحتفاظ بها قبل استخدام سجلات حقيقية.
2. **السياسات البنكية:** إدخال جداول البنوك الفعلية الموثّقة وتاريخ سريانها، ومتغيرات مثل تحويل الراتب والدعم والجهة الوظيفية والمصاريف والرسوم، واختبارات قبول لكل بنك.
3. **طلب التمويل:** قائمة مستندات قابلة للمتابعة، سجل زمني للحالة، ملحقات مشفّرة ومحكومة الصلاحيات، وتتبع مباشر للتواصل مع البنك إن توفرت واجهة رسمية مناسبة.
4. **التحصيل:** دعم تكرارات الدفع غير الشهرية والعقود المتغيرة والإيجار الجزئي والتسويات وسندات القبض المتوافقة مع المتطلبات، وتذكيرات المستأجرين بعد إعداد موافقتهم وقناة اتصال مناسبة.
5. **جودة المنتج:** اختبارات تفاعل end-to-end، مراجعة محاسبية/ائتمانية مستقلة، مراقبة أخطاء ونسخ احتياطي آلي آمن.

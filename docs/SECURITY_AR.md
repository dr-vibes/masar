# سياسة الأمان والبيانات — قبل الاستخدام الحقيقي

## ما هو مؤمّن وما ليس مؤمّنًا
| الطبقة | الحالي | القصور/العمل المطلوب |
|---|---|---|
| الاتصال | HTTPS + تحويل 301 | المحافظة على التجديد والتحديث وفحص الشهادة |
| بوابة الموقع | Nginx Basic Auth | حساب مشترك غير كافٍ لتدقيق الأفراد أو MFA؛ لا يوجد Logout تطبيقي مؤكد |
| الشبكة | SG 22 مقيّد إلى /32؛ 80 و443 متاحان | راجع تغيّر IP وقيود الإدارة؛ لا تفتح منافذ قواعد البيانات |
| تخزين بيانات العمل | `localStorage` ونسخ JSON يدوية غير مشفرة | لا تخزن بيانات حقيقية؛ يلزم قاعدة مؤمنة ومفاتيح وصلاحيات وسياسة نسخ |
| أمان التطبيق | حاسبة وواجهة فقط؛ لا Backend | يلزم مصادقة تطبيقية/تفويض/سجل تدقيق/تحقق مدخلات جهة الخادم |
| السياسات البنكية | نسب وقواعد قابلة للتحرير | غير معتمدة؛ مصدر وتاريخ سريان وموافقة مختص |
| النسخ الاحتياطي | Snapshot للخادم (مكتمل بحسب المستخدم) | لا يحفظ `localStorage`؛ إجراء استعادة غير مختبر |
| التبعيات | ظهور تحذير ثغرتين متوسطتين في npm | فحص تفصيلي ثم تحديث مستهدف مع اختبار؛ لا تستخدم `--force` بلا تقييم |

## قواعد بيانات وسلوك محرّمة حتى الإطلاق الفعلي
- ممنوع إدخال أسماء/أرقام جوالات/دخل/هويات/حسابات بنكية أو صور مستندات حقيقية في البيئة الحالية، إلا إذا تمت مراجعة رسمية واعتماد البنية والأمان من المؤسسة.
- ممنوع نشر `.env`، ملفات JSON احتياطية حقيقية، مفاتيح SSH، كلمات مرور حسابات، `.masar_htpasswd`، أسرار Certbot أو private keys، أو نتائج تحتوي معلومات شخصية.
- لا تسجل مفاتيح في ملفات التوثيق أو في رسائل AI؛ استخدم أسماء متغيرات وأمثلة وهمية.
- لا تعتمد على Basic Auth وحده بدل تسجيل دخول بمستخدمين مستقلين وأقل صلاحية ومراقبة وتسجيل محاولة الدخول.
- لا تفترض أن Cloudflare يحمي الأصل تلقائيًا: السجل الحالي `DNS only` بحسب خطوات الإنشاء؛ EC2 مكشوف عبر SG للمنافذ العامة اللازمة.
- لا تعطِّل وصول HTTP دون التأكد من أثره على ACME/تجديد Let's Encrypt.

## شروط السماح ببيانات عملاء فعلية (بوابات قبول)
1. اعتماد المؤسسة لنطاق الاستخدام وسياسة التعامل مع البيانات والأغراض والموافقات وحدود الاحتفاظ والاستضافة.
2. مصادقة تطبيقية آمنة مع MFA إن أمكن، صلاحيات لكل مستخدم، جلسات مضبوطة وتدقيق للوصول.
3. تخزين موثوق مشفر ونقل مشفر، نسخ احتياطي مجدول ومجرّب الاستعادة، وحذف/تصحيح بيانات موثق.
4. مراجعة أمنية للاعتمادات، والتحقق من المدخلات على الخادم، وتجارب تجاوز صلاحيات ومراقبة الأخطاء.
5. توثيق مصادر سياسات البنوك والرسوم والحدود واعتماد الحسابات والنتائج مع المختصين، والإفصاح للعميل عن كون التقدير غير ملزم.
6. اختبار وظائف الإيجارات والتسويات والتواريخ والاستحقاقات وسجلات التغيير بإجراءات تدقيق.

## استجابة أولية للحوادث (دليل تنظيمي، لم تُختبر خطة كاملة)
- لا تحذف سجلات أو بيانات قبل تثبيت الأدلة؛ حدِّد نطاق الوصول والضرر المحتمل.
- إذا اشتُبه بتسريب كلمة مرور Basic Auth: غيّرها على الخادم من خلال قناة آمنة، وراجع سجلات الوصول ومدى الحاجة لإبلاغ المؤسسة.
- احفظ التوقيت والمنفذ/المكوّن المتأثر والإجراء والنتيجة في `CHANGELOG.md` **من دون أي بيانات حساسة**.
- توثيق استعادة/إلغاء تغييرات الإنتاج ضروري قبل نشر إصلاح قد يحجب الوصول إلى الخدمة.

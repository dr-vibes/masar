# المعمارية الحالية والتصميم المستهدف

## المعمارية الفعلية في نسخة V2 (مراجعة المصدر)

```text
المتصفح (React 18 + TypeScript + Router + Tailwind)
  ├─ /app                لوحة العمل
  ├─ /app/calculator     الحسابات
  ├─ /app/compare        مقارنة البنوك
  ├─ /app/clients        متابعة طلب التمويل
  ├─ /app/rentals        المشاريع والوحدات والتحصيل
  └─ /app/rates          القواعد والإعدادات والتصدير
           ↓
    React Context / src/app/store.tsx
           ↓
    localStorage: masar.personal.v2
           ↘ ملفات JSON يدوية للتصدير/الاستعادة

محرك مالي: src/lib/finance.ts  | محرك إيجارات: src/lib/rentals.ts
اختبارات: scripts/verify.mjs
```

- `src/lib/sample.ts`: العملاء/البنوك والسياسات الافتراضية التجريبية.
- `src/app/Rates.tsx`: تحرير شروط كل بنك وشرائح التسعير؛ الشريحة المطابقة الأولى هي المستخدمة.
- `src/app/Clients.tsx`: تسجيل مراحل الطلبات ومرجع البنك والمتابعة، وليس رفع الطلب للبنك إلكترونيًا.
- `src/app/Rentals.tsx`: تسجيل التحصيل داخليًا، وليس بوابة دفع أو ربطًا بنظام إيجار.
- `src/main.tsx`: مسارات SPA تبدأ من `/app`؛ لا توجد طبقة Auth داخل React.
- `package.json`: `npm test` (فحص المصدر والمنطق)، `npm run build` (tsc -b + vite)، و`npm run dev`.
- `netlify.toml`: إعداد نشر قديم/بديل؛ **الواجهة التي اختبرها المستخدم حاليًا منشورة على AWS EC2/Nginx**، ولا يوجد دليل أن Netlify ما زال وجهة الإنتاج.

## المعمارية التشغيلية المثبتة من الحوار

```text
متصفح المستخدم → DNS لدى Cloudflare (سجل A مؤقت DNS only)
              → masar.ah-nova.tech → AWS EC2 / Ubuntu 22.04
              → Nginx :80 (301 إلى HTTPS)
              → Nginx :443 (Let's Encrypt + Basic Auth)
              → /var/www/masar (ملفات dist المبنية)
              → localStorage في متصفح كل جهاز
```

**قيد جوهري:** لا توجد API ولا قاعدة بيانات خلف هذه الواجهة. تشفير النقل وتسجيل الدخول على Nginx لا يشفّران بيانات المتصفح المخزنة ولا يضمنان تاريخًا أو سجل تدقيق موثوقًا.

## التصميم المستهدف للاستخدام الفعلي (لم يُنفذ بعد)

```text
React UI / HTTPS
       ↓
مصادقة تطبيقية مع MFA وجلسات مضبوطة
       ↓
API خلفية + صلاحيات منظمة (مستخدم واحد أولًا؛ إمكانية إضافة زملاء لاحقًا)
       ↓
PostgreSQL + تشفير وحوكمة وصول + تدقيق تغيير
       ├── بيانات العملاء وملفات الاستحقاق المحفوظة
       ├── نسخ سياسات البنوك ومصادرها وتواريخ سريانها
       ├── طلبات التمويل وسجل انتقال الحالة
       └── المشاريع/الوحدات/العقود/دفعات الإيجار
```

الاختيار بين Supabase/PostgreSQL مُدار أو خلفية مستضافة على AWS **قرار مفتوح**؛ لا تعتمد خدمة قبل مراجعة متطلبات المؤسسة والخصوصية والتكلفة ومكان البيانات. افصل بيانات العملاء عن بيانات البنوك والأمثلة، ولا تحوّل السجلات الحالية إلى الإنتاج بصمت.

## حدود الحساب البنكي
- نسب البنوك التجريبية لا تُعرض بوصفها أسعارًا رسمية؛ مطلوب مصدر وتاريخ لكل شريحة، وحالات مرجعية معتمدة لكل بنك.
- `finance.ts` ليس محرك موافقات أو تحقق نهائي من ضوابط ساما أو رسوم APR.
- عند تحديث أي قاعدة، أضف اختبارات للراتب (بما فيه 0 وحد 15000) والعمر والقطاع والدعم وتحويل الراتب والالتزامات والمدد والحساب المرن/الثابت.

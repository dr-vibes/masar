## أولويات العمل التالية بالتحديد

**P0 — أولًا:**
1. التحقق من اكتمال تحديث Ubuntu الذي جرى بعد إنشاء EBS Snapshot: أولوية الرد التالي في حوار نشر AWS هي فحص حالة الموقع المحمي عبر `curl -I https://masar.ah-nova.tech` (النتيجة المتوقعة `401`)، ثم التأكد من حزم apt المتبقية إن نجح الفحص. **لم يرد بعد ناتج هذه الخطوة**.
2. حفظ وثائق النسخة الجديدة داخل المستودع الأصلي ثم التأكد من وجودها على جهاز العمل/الخادم؛ لم تنقلها هذه المهمة تلقائيًا إلى AWS.
3. مراجعة `npm audit` للثغرتين المتوسطتين؛ لا تستخدم `npm audit fix --force` عشوائيًا.
4. تأكيد ثبات عنوان AWS العام (Elastic IP أو بديل) وسجل Cloudflare، ومراجعة صلاحيات SSH.

**P1 — قبل استخدام أي بيانات عميل فعلية:**
1. تحديد متطلبات المؤسسة القانونية والخصوصية وإدارة الوصول، واختيار قاعدة بيانات وحماية الأسرار والنسخ والاسترجاع.
2. تنفيذ مصادقة حقيقية لمستخدم التطبيق، وربط السجلات بالهوية، وسجل أنشطة والحد الأدنى للامتيازات.
3. اختبارات حذف بيانات/استعادة/انقطاع المتصفح وتجربة الوصول من جهاز مصرح وآخر غير مصرح.

**P2 — قبل الاستناد إلى التقدير في توصية عمل للعميل:**
1. الحصول على سياسات كل بنك وتواريخ سريانها، والعروض والرسوم وطريقة حساب الربح وقابلية تحويل الراتب والدعم.
2. مطابقة 10–20 حالة واقعية مجهولة الهوية **بموافقة المؤسسة** لكل بنك مع المخرجات المعتمدة.
3. مراجعة الحدود النظامية والافتراضات لدى مختص مرخص دون الادعاء أن جميع الحسابات موافقة لساما.

**P3 — بعد إنهاء P1 وP2:**
تحسين ملف العميل، المواعيد، المستندات المشفرة، تكرارات الإيجار غير الشهرية، الدفعات المسبقة والتسويات، كشوف العملاء وتقارير PDF.

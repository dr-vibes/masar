## فحوص سريعة غير مغيرة للخادم
```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
curl -I https://masar.ah-nova.tech
curl -I http://masar.ah-nova.tech
sudo systemctl status snap.certbot.renew.timer --no-pager
apt list --upgradable
```
- HTTPS دون بيانات اعتماد: **401** متوقع؛ يثبت الاستجابة والحماية. مع بيانات الاعتماد يكون المحتوى متاحًا، **لا تضع كلمة مرور في سطر أوامر `curl` أو سجلات الطرفية**.
- HTTP: **301 Location: https://masar.ah-nova.tech/** متوقع.
- راجع انتهاء صلاحية الشهادة: `sudo /snap/bin/certbot certificates` (لا تخرج مفاتيح خاصة).
- عند تعارض الحالة مع هذا الدليل: **لا تعالج عشوائيًا**؛ حدّث الوثائق بعد التحقق.

## نشر إصدار جديد يدويًا — إجراء مستقبلي بعد الموافقة
1. افحص نسخة Git/المصدر وتأكد من عدم وجود بيانات حقيقية في الكود أو الملفات.
2. سجّل إصدار النشر وتاريخ العمل في `CHANGELOG.md`، وأنشئ نسخة من مجلد الملفات المنشورة قبل الاستبدال.
3. داخل مجلد المصدر نفذ `npm ci` ثم `npm test` ثم `npm run build`، كل عملية على حدة مع مراجعة نتيجتها.
4. تحقق من وجود `dist/index.html` و`dist/assets`، وأن الوثائق الجديدة موجودة في المصدر إن كان التحديث يشملها.
5. انقل **محتويات** `dist/` فقط إلى `/var/www/masar/` باستخدام `rsync` بعد تأكيد مسار المصدر والهدف. لا تستخدم `--delete` بلا نسخة سابقة أو مراجعة الأثر.
6. افحص `nginx -t` إن عُدلت إعدادات الموقع، ثم `systemctl reload nginx` عند الحاجة.
7. تحقق HTTPS/Basic Auth/الصفحات الأساسية `/app` و`/app/calculator` و`/app/rentals`، واكتب النتيجة في `CHANGELOG.md`.

## التعامل مع Nginx وBasic Auth
- شهادة Let's Encrypt أُضيفت بواسطة Certbot إلى كتلة HTTPS 443 في ملف `masar`.
- الموقع يعمل بـ `auth_basic` و`auth_basic_user_file` في **كتلة HTTPS**، مع إبقاء تحويل المنفذ 80 إلى 443.
- أصل إعداد Nginx الأولي موجود خارج المصدر في ملف `masar-aws-nginx.conf` الذي رُفع عند التأسيس؛ **لا تستبدل به إعداد الإنتاج الحالي** لأنه لا يحتوي على تغييرات Certbot والحماية.
- لا ترفع `.masar_htpasswd` إلى Git؛ عدم القدرة على استعادة هذا الملف بعد فقد الخادم تتطلب إجراء إعادة إنشاء آمن بدل نشره.
- إذا تغيّرت حواسيبك/شبكتك، افحص قاعدة SSH المقيدة قبل قطع جلسة AWS الحالية.

## TLS
- Certbot Snap `certbot renew --dry-run` نجح قبل وبعد Basic Auth، والمؤقت التلقائي enabled/active في آخر فحص.
- إذا فشل التجديد لاحقًا، افحص سجلات Certbot وDNS ووصول المنفذ 80 مع إبقاء فحوصات الأمن، لا تعطل Basic Auth عن كل الموقع دون تحليل.
- لا تخزّن نسخ مفاتيح Let's Encrypt الخاصة داخل المستودع/المرفقات.

## تحديث نظام Ubuntu (آخر عملية مفتوحة)
- EBS Snapshot قبل العملية بحالة Completed وفق إفادة المالك.
- `sudo apt-get -s upgrade` عرض تحديث 10 حزم منها `libc6` و`perl` دون حذف.
- `sudo apt-get upgrade -y` وصل نافذة `needrestart`، ثم أظهر إعادة تشغيل خدمات وتأجيل تشغيل `ssh` و`nginx` وخدمات الشبكة. **لم يُقدّم بعد ناتج فحص لاحق لحالة التطبيق أو قائمة تحديثات apt**.
- **أول إجراء متفق عليه مع المستخدم عندما نعود للعمل على الخادم:** `curl -I https://masar.ah-nova.tech`، ثم بعد الاطلاع على النتيجة نقرر الفحص التالي. لا تعِد تشغيل الشبكة أو SSH عن بُعد دون خطة لاسترجاع الاتصال.

## النسخ الاحتياطي والتراجع
- Snapshot يعالج أقراص الخادم المختارة، **لا يعالج بيانات `localStorage` في متصفحات المستخدمين**.
- لم تُجرّب استعادة Snapshot فعليًا؛ أدخل اختبار استعادة منفصل في الخطة قبل الاعتماد.
- للرجوع عن إصدار واجهة فاشل: استعد مجلد `/var/www/masar` من نسخة إصدار سابقة معروفة، ثم افحص HTTP/HTTPS/المسارات. لا تعتمد على Git rollback وحده إذا لم يحتفظ `dist` السابق.
- لا تعِد تشغيل/توقف المثيل دون التأكد من IP ثابت أو أثره على Cloudflare.

## ملاحظة أمنية ملزمة
حتى مع TLS وBasic Auth وSG، **ما زالت بيانات العمل في المتصفح**؛ لا تستخدم ملفات العملاء الحقيقية قبل خطة قاعدة بيانات/تشفير/صلاحيات/حوكمة مُعتمدة. لا تضف كلمات المرور أو الهويات أو عناوين اتصال خاصة إلى `CHANGELOG.md`.

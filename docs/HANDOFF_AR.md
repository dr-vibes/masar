# تسليم السياق — نقطة استئناف العمل

**تاريخ التحديث:** 2026-11-18\
**النطاق:** حالة مصدر مشروع مسار على AWS وخطوة الاستئناف قبل أول رفع إلى GitHub.\
**مصدر الإثبات:** مخرجات أوامر Ubuntu ونتائج الاختبارات التي شاركها المستخدم، مع إفاداته عن إعدادات AWS/Cloudflare.\
**مهم:** هذه نسخة مُعدّة للدمج؛ لا تعتبر موجودة داخل مصدر AWS أو GitHub حتى تُرفع وتُفحص هناك.

## الهدف وقواعد العمل
- «مسار» أداة استخدام شخصي داخل مؤسسة وساطة عقارية: حساب التمويل حسب حالة العميل وسياسات البنك، ومقارنة الخيارات، ومتابعة ملفات رفع التمويل، وإدارة المشاريع وتحصيل الإيجارات.
- المنصة الحالية **واجهة React/Vite**؛ بيانات التطبيق تحفظ محليًا في `localStorage`، ولا توجد قاعدة بيانات مشتركة أو مصادقة تطبيقية أو أذونات مستخدمين.
- نعمل باللغة العربية، وعلى الخادم **خطوة واحدة ثم تحقق ثم توثيق ثم انتقال**؛ لا ننفذ تغييرات مجمعة دون مراجعة.
- يجب تسجيل كل تغيير في `CHANGELOG.md` وتحديث هذه الوثيقة عند انتهاء المهمة؛ راجع `AGENTS.md` و`docs/AI_WORKFLOW_AR.md`.

## آخر حالة ناجحة ومثبتة
- **المصدر على AWS:** `/home/ubuntu/deployments/masar-v2/masar-personal-v2`، منفصل عن المجلد القديم `msar-project`.
- **الإنتاج على AWS:** محتويات `dist/` نُسخت سابقًا إلى `/var/www/masar` وتخدمها Nginx. دمج التوثيق وإعادة بناء المصدر لاحقًا **لم يتضمنا** نسخ `dist/` الجديد إلى مجلد الإنتاج.
- **الدومين:** `masar.ah-nova.tech` ضمن نطاق `ah-nova.tech` عبر Cloudflare. أكد المستخدم تحديث سجل `A` إلى **Elastic IP `18.170.245.85`** وربطه بالمثيل نفسه. IP السابق `52.56.136.16` محفوظ لأغراض تاريخية فقط.
- **اختبار HTTPS على العنوان الجديد:** نجح الأمر `curl -I --resolve masar.ah-nova.tech:443:18.170.245.85 https://masar.ah-nova.tech` وأعاد `401 Unauthorized` مع `WWW-Authenticate: Basic realm="MASAR - Private Access"`، دون خطأ شهادة. هذا يثبت وصول الخدمة إلى IP الجديد واستمرار حماية Nginx Basic Auth وقت الاختبار.
- **HTTPS والتجديد:** صدرت شهادة Let's Encrypt باستخدام Certbot Snap؛ نجح `certbot renew --dry-run` بعد تفعيل Basic Auth. ظهر مؤقت `snap.certbot.renew.timer` في حالة `enabled` و`active (waiting)` وقت التحقق.
- **اختبارات التطبيق:** `npm test` نجح (15 ملفًا دون أخطاء صياغة؛ سيناريوهات التمويل والإيجارات الأساسية)، و`npm run build` نجح (Vite 6.4.6، 43 وحدة)، بعد دمج ملفات التوثيق في مصدر AWS.
- **اختبار التوثيق:** `npm run docs:check` نجح برسالة `Documentation check passed (13 required files)` بعد دمج ملفات التوثيق في المصدر.
- **نسخ احتياطية:** المستخدم أكد أن EBS Snapshot قبل تحديث Ubuntu وصلت إلى `Completed`، كما أُنشئ أرشيف محلي للمصدر قبل دمج التوثيق: `/home/ubuntu/deployments/masar-source-before-docs-2026-11-17.tar.gz`. لا يوجد اختبار موثق للاستعادة.
- **سجل الدمج:** أضيف القيد `CHG-20261117-02` في `CHANGELOG.md` بعد نجاح الدمج والاختبارات.
- **انتقال IP:** أضيف الحدث `H-23` بتاريخ 2026-11-18 في `docs/HISTORY_AR.md` والقيد `CHG-20261118-01` في `CHANGELOG.md`؛ أكد المستخدم محتوى القيد. أفاد المستخدم بأنه حدّث عنوان IP في `docs/AWS_RUNBOOK_AR.md`.
- **GitHub:** لم يتأكد إنشاء/تحديث مستودع رسمي مطابق للمصدر الحالي أو دفع هذه الملفات إليه. إعدادات `.github/workflows/quality.yml` موجودة داخل المصدر لكنها لم تُختبر بعد على GitHub.

## أول خطوة واحدة قادمة على خادم AWS
**المهمة الحالية:** تحديث ملف `docs/HANDOFF_AR.md` بهذه النسخة بعد **التحقق من بصمتها**، مع حفظ النسخة الموجودة أولًا. لا تستبدل الملف أثناء خطوة رفعه أو خطوة فحص بصمته. بعد الاستبدال، شغّل `npm run docs:check` وتحقق من القيد `CHG-20261118-01` دون تعديل الكود أو إعادة نشر الموقع.

**بعد اعتماد هذه الوثيقة:** تجهيز نسخة قراءة فقط من مصدر AWS للمراجعة النهائية قبل GitHub، وفحص `.gitignore` وملفات الأسرار والاعتمادات والوثائق، ثم إجراء أول رفع إلى مستودع **Private** بعد مراجعة الملفات التي سيتتبعها Git.

## مسائل مفتوحة ومخاطر يجب ألا تُعتبر منجزة
1. **تحديث Ubuntu:** أظهر `apt-get upgrade -y` شاشة `needrestart` وخدمات أُعيد تشغيلها وأخرى أُجّل تشغيلها. ثبت لاحقًا أن الموقع يستجيب عبر HTTPS مع Basic Auth (`401`)؛ **لكن لم يُفحص حتى الآن** ناتج `apt list --upgradable` بعد التحديث أو وضع كل خدمة مؤجلة، لذلك لا تدّعِ اكتمال الصيانة بصورة شاملة.
2. **حماية البيانات:** Basic Auth يحمي واجهة الموقع على مستوى Nginx، لكنه ليس نظام حسابات وصلاحيات داخل التطبيق؛ و`localStorage` ليس تخزينًا خادميًا أو نسخة احتياطية للبيانات. لا تستخدم بيانات عملاء حقيقية حتى تُبنى طبقة خلفية آمنة وسياسات خصوصية ونسخ احتياطي.
3. **التبعيات:** ظهرت سابقًا ثغرتان متوسطتا الخطورة في تدقيق npm؛ لم تثبت معالجتهما. لا تستخدم `npm audit fix --force` دون مراجعة وتقييم واختبار.
4. **الحسابات:** نسب البنك وقواعد الأهلية تجريبية/قابلة للتعديل؛ ليست عروضًا مؤكدة ولا اعتمادًا تنظيميًا أو مصرفيًا. يلزم التحقق من السياسات الرسمية وحالات الاختبار المرجعية.
5. **الاختبارات:** لا يوجد إثبات لاختبارات تكامل/متصفح شاملة، أو فحص اختراق، أو مراجعة مطابقة تنظيمية.
6. **DNS والخادم:** تم التحقق من وصول HTTPS إلى Elastic IP الثابت الجديد؛ لا تغَيّر Cloudflare أو Nginx أو شهادة TLS دون مهمة مستقلة ونسخة احتياطية وفحص.
7. **GitHub:** لا ترفع ملفات `node_modules/` أو `dist/` أو ملفات `.env` الفعلية أو مفاتيح/شهادات TLS أو ملف `htpasswd` أو بيانات عملاء أو أرشيفات النسخ الاحتياطية. راجع `.gitignore` وقائمة الملفات المتتبعة قبل أي Commit.
8. **خريطة التطوير:** تبقى أولوية بناء قاعدة بيانات ومصادقة آمنة، ثم تدقيق قواعد البنوك والتقارير وسير رفع الطلبات وتحصيل الإيجارات؛ راجع `docs/ROADMAP_AR.md`.

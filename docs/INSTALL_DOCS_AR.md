# دليل نقل نظام التوثيق — مرجع تاريخي

> **الحالة في 2026-11-18:** تم دمج التوثيق في مصدر مسار على AWS واجتاز فحص docs:check. لم يُرفع المشروع إلى GitHub بعد. تعليمات النقل أدناه مرجع عند الحاجة، وليست خطوات مطلوبة الآن.

## ماذا استلمت؟
- `MASAR_V2_Documented_2026-11-17.zip`: مصدر المشروع V2 كاملًا مضافًا إليه التوثيق والقواعد وفحصها.
- `MASAR_Docs_Overlay_2026-11-17.zip`: الملفات التي أضيفت أو تغيرت فقط داخل مسار `masar-personal-v2/`.

## الإجراءات المنطقية للنقل (ليس أمرًا للتنفيذ دفعة واحدة)
1. **قبل أي رفع:** افحص حالة الموقع والخادم بعد آخر تحديثات Ubuntu (راجع `docs/HANDOFF_AR.md`). لا نؤخر هذا الفحص من أجل التوثيق.
2. **على جهازك/بيئة Git:** أنشئ commit واضحًا لملفات التوثيق و`package.json` وملفات الفحص. إن كان المستودع قد تغيّر منذ ZIP المرجعي، راجع الفرق ولا تستبدل شفرته بنسخة قديمة.
3. **إذا رغبت نقل الوثائق مباشرة إلى السيرفر:** ارفع الأرشيف *الجزئي* إلى `/home/ubuntu/` باستخدام SFTP، وافحص أسماء ملفاته باستخدام `unzip -l` قبل الاستخراج، ثم انقل الملفات إلى مجلد المصدر بعد الاحتفاظ بنسخة من أي ملف سيتم استبداله. لا ترفع الأرشيف إلى `/var/www/masar` (مجلد الموقع العام).
4. **اختبر وجود الملفات:** `npm run docs:check` من داخل مجلد المصدر المحدث.
5. **اختبر الكود بعد الدمج:** `npm test` و`npm run build` عندما تكون البيئة جاهزة، دون إعادة نشر الواجهة إن لم تكن هناك تغييرات وظيفية.
6. **سجّل واقع الدمج:** عند اكتمال النقل، أضف إدخالًا جديدًا إلى `CHANGELOG.md` يفرق بين الرفع إلى AWS وGitHub، وحدّث `docs/HANDOFF_AR.md`.

## حدود مهمة
- لا تستخدم أمرًا عامًا مثل `unzip -o` في مجلد إنتاج قائم دون مقارنة الملفات؛ قد يمحو نسخة أحدث من README أو package.json أو إعدادات أخرى.
- لا تضم سجلات أو معلومات عملاء ولا مفاتيح أو أسرار خادم إلى التوثيق.
- إن كنت تستخدم GitHub Actions، لا تبدأ تنفيذه قبل مراجعة صلاحيات المستودع وفحص فرق العمل؛ الـ workflow هنا **يتحقق من الجودة فقط، ولا يرفع إلى AWS**.
